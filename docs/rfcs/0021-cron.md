# RFC 0021 — Cron in hevd

Status: Phase 1 implemented

## Summary

Run a bounded argv on a regular interval or at a local clock time using the
existing daemon across Linux, macOS and Windows.

## Motivation

Host-specific timers duplicate installation and provide separate logs,
credentials and failure reporting. A native job can use kit's in-memory
secrets cache and attention outbox.

## Decision

Use `[[cron]]` in daemon configuration and the [jobs CLI](../cron.md) for
inspection, immediate execution and local pause/resume. Keep private
per-job state and bounded, redacted history on disk. Coordinate local
executions with OS file locks shared by the CLI and daemon.

## Goals

Bound process lifetimes, retention and captured output. Allow a configured
job to move between alive hosts without an elected leader.

## Non-goals

Missed-tick replay, arbitrary cron expressions, remote command distribution,
distributed locking and exactly-once execution.

## Vocabulary

A tick is a scheduled opportunity to execute. The placement winner is the
alive configured member with the highest rendezvous score in this member's view.

## Proposed surface

See [cron](../cron.md) for configuration, retention, notices and CLI.
Publish only a bounded cooldown deadline through SWIM. Commands, references,
output and state remain local.

## Open questions

Whether a later phase needs explicit leases and fencing for work that cannot
tolerate duplicate execution during membership convergence.
