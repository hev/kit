Registration probe input is strict `RegistrationRequest`: `version`, `enrollment`, `node_uid`, `incarnation`, `admission_generation`, and paired optional `descriptor_ref` / `descriptor_digest`. Before every new dispatch, both descriptor fields are supplied. The receiver uses read-only SQLite access to verify the original job, request digest and physical StartAuthority before the neutral Factory maintenance projection. Registration-only calls may omit the descriptor; these are never admission permits. Output uses the six registration fields listed above.

Registration is stored in the original descriptor directory as `host-registration.json`, including the configured profile digest and real hevd birth. `host-intent.json` is exclusive transport deduplication, never a second job/result store. A crash between either marker and receiver birth is held for inspection; neither marker is removed to retry. Original journal completion and exact ACK remain authoritative.

The existing managed unit retains `KillMode=control-group`. Caller/controller death is separate from hevd death. A daemon restart can terminate its receiver/workload descendants; an interrupted original remains Uncertain until reconciled. The host does not adopt a PID, reissue native fences, release capacity or manufacture a terminal result. No tmux dependency or new daemon is introduced. Nativehost IPC remains Linux-only; Darwin and Windows are held pending separate native role proofs.

The first source composition uses the optional adapter's pinned Factory registration facade and a pinned root SDK. Final integration must test the exact selected pair and installed managed unit. Root unit tests use a controlled registration fixture, not PG/maintenance acceptance. Historical source and tmux receipts do not transfer acceptance.

Runtime interpreter validation is static and performs no IPC, child execution, authentication or database access. Every declared script and the fixed supervisor's shebang is checked. Direct interpreter paths and `/usr/bin/env NAME` resolve to exact canonical `runtime.files` pins. The first executable on the explicit PATH wins; an earlier unpinned Node/Python shadow holds even if every declared file hash is unchanged. A normal venv or system dependency alias may be a symlink only when its resolved target is exactly the declared pinned file. Managed supervisor/config targets remain nonsymlinks. Plain whitespace-separated `env -S` is supported; ambiguous options, assignments, quoting, expansion and non-ASCII/control-character shebangs are held. A multiword env argument without `-S` is held rather than parsed differently from the kernel.

`hev native-job inspect-original --root ABS --host H --executor E --job ID` returns `native-owner-proof/v1` metadata using `nativejob.ReadOnlyProof`, never initializing `Open`. It includes explicit enrollment, original identity/request digest/StartAuthority, persisted `owner_birth` and `child_birth`, original completion and historical ACK, and `observed_at`. No argv or environment is serialized. Omit `--job` only for enrollment observation, which omits all job facts. Persisted births are not liveness, adoption, descendant termination or a capacity-release permit; the floor consumer must separately verify fresh exact original and tree-terminal evidence.
