What the trace makes obvious

    How this prototype was joined

    These 22 worker sessions and the FOH session are real (Oct 23–24). Nothing in the archive links them today, so they were matched by hand: Oven workdirs named after the order, Mini sessions whose first prompt is a peer message from foh-hev-3, plus timestamps. In the RFC that becomes exact: the daemon stamps trace_id = order UID and the run span on each worker, and hev apply records the FOH turn.

    Gaps this exposes

    • Run records have no start/end times; spans here use session times.
    • None of these sessions has a summary (order kit-trace-summaries). Labels are written from each worker's final message.
    • Kit stores the Mini sessions' skill call as just “Skill”; browser-use was read from the raw transcripts (order kit-skill-capture). Codex skill loads aren't detected at all.
    • Validation was filed as separate legacy orders; under the RFC they are spans of this one.
