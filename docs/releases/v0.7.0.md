## In this release so far

Merged to `main` since v0.6.2. Upgrade with
`brew update && brew upgrade hev/tap/hev`.

- **The board needs no setup.** `hev board serve` with no hev layer key keeps
  the board in files under `~/.hev/board/` (`board.dir` or `HEV_BOARD_DIR`
  moves it) and needs no namespace or endpoint. Search matches words, and
  every command, filter and route works as before. With a key the board uses
  hev layer as it always has. `hev board whoami` and the server's startup line
  say which. An existing hev layer board must keep its key in the server's
  environment: without one it now starts on an empty board in files.
  See [Board](https://hevkit.com/docs/board#run-a-board-server).
  ([#189](https://github.com/hev/kit/pull/189))
- **Short invite codes for shared hosts.** `hev nodes invite alex` prints a
  code like `7K-Q4M2-XPWD`; the member runs
  `hev nodes join bot@HOST 7K-Q4M2-XPWD`, and the owner approves by name with
  `hev nodes pending` and `hev nodes accept alex`. The code is single use,
  expires, and locks after five wrong tries. The exchange runs over the host's
  existing sshd, opens no port, and a host that does not know the code cannot
  pass itself off as the owner's. `invite` also takes `--allow repos` and
  `--administrators`, and `hev nodes remove NAME` withdraws an open
  invitation. Invitations sent with the long codes keep working, and
  `hev nodes invite --long` still makes one.
  ([#183](https://github.com/hev/kit/pull/183))
- **Runs end done, blocked or needs-decision.** A dispatched worker finishes
  by naming its outcome. `hev dispatch ls` shows blocked runs and open
  decisions by default, with a new `DECISION` column, and notifications lead
  with the outcome. Answer a decision with
  `hev dispatch say NAME --resolve KEY "answer"`: the run is reworked on the
  same worktree, branch and PR, and every later prompt repeats the answer.
  A run with an open decision is not sent to browser validation.
  ([#184](https://github.com/hev/kit/pull/184))
- **`hev peers` matches the Python peers.** The `peers` commands, flags,
  output and state files are now built into `hev`, byte for byte compatible
  with the Python `peers`, so the two run side by side on one host and across
  hosts. A `peers` symlink to `hev` behaves like the Python executable.
  ([#180](https://github.com/hev/kit/pull/180))

### Fixed

- **`hev s` on macOS sees the running daemon.** Since 0.6.1, `hev s` printed
  `Daemon: stopped` on every Mac while hevd ran under launchd, and
  `hev daemon stop` could not find it. hev now asks launchd for this user's
  hevd. ([#171](https://github.com/hev/kit/pull/171))

### Removed

- **`hev get`, `apply`, `describe`, `logs`, `wait`, `api-resources`,
  `controller`, `orders` and `runs`.** These forwarded to a coordination
  backend that is gone. Each now exits 1 with a message pointing at
  `hev dispatch` and `hev orchestrate`; nothing is run from `PATH`, and
  `HEV_RESOURCE_BACKEND` and `HEV_COORDINATION_BACKEND` are no longer read.
  Bare `hev` reports peers only.
  ([#174](https://github.com/hev/kit/pull/174))

### Docs

- hevkit.com's source now lives in this repository under `site/`, so a
  feature's docs ship in the same change as the feature. It includes the
  [Join a host](https://hevkit.com/docs/join-a-host) and
  [Share a host](https://hevkit.com/docs/share-a-host) guides.
  ([#129](https://github.com/hev/kit/pull/129))
