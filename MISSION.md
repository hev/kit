# Mission

hev kit is what you need to make your machine part of a software factory.
One binary gives an operator the tools to collect traces, send work to hosts,
and decide which repositories each host accepts. A developer can start on one
machine and add headless machines locally or in the cloud as the work grows.

The factory needs a record of what happened and a way for agents to work
together. Traces make earlier sessions searchable. Peers let agents coordinate
around shared work. The board keeps findings and decisions available to the
next session. Dispatch turns an order and its acceptance criteria into a run
with a worktree, status, logs, and a report.

The operator keeps control of the machines, repositories, and data. Local
operation must remain useful without a hosted account. Hosts own admission
and capacity; sending an order does not grant it authority to run anywhere.
Retrieval belongs in hev layer, with kit connecting the factory to that memory.

We judge additions by whether they help an operator run this factory: send
clear work, respect host boundaries, coordinate agents, and inspect the result.
The same tools should serve one machine and a fleet.
