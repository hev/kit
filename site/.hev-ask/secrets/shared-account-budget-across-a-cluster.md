With a cluster configured, daemons gossip only numeric reservation counts so hosts can enforce a shared account-level daily and hourly budget on top of each host's own limits, falling back to host budgets when peers are not visible; enforcement is eventually consistent and not guaranteed during partitions. The section also covers propagated cooldowns, a single meter host, unexplained-spending signals, serving stale values during a rate limit, running a separate secrets-only service as the long-lived cache owner, owner-only cross-host attribution, and the rule to resolve once and reuse rather than fetch per launch or poll.
