kit never signs in to Azure interactively; the daemon needs one credential: managed identity on an Azure VM, Arc server or App Service, Kubernetes workload identity, a service principal with a certificate or client secret, or an existing Azure CLI login for workstations. Without an explicit choice kit tries client secret, certificate, workload identity, then a platform identity endpoint, and callers must hold the same credential for the daemon to serve them. Prefer secretless identities, keep any client secret as a reference in another store (a Key Vault reference would be a cycle and is refused), and configure DNS suffix and authority host for Azure Stack Hub.
