kit never signs in to Azure interactively; you set one credential in the daemon's environment: managed identity (VM, Arc or App Service), Kubernetes workload identity, a service principal with certificate or client secret, or an existing Azure CLI login for workstations. It auto-selects in a fixed order unless told, callers must hold the same credential, secretless credentials are preferred, and a client secret should be supplied as a reference from another store since a cycle back to Key Vault is refused.
