hev kit is a **meta-harness**. A harness such as Claude Code or Codex runs one
agent session. kit sits one level up: it is a set of tools that work across
harnesses, sessions and machines, packaged as a single `hev` binary that runs
on every major OS: macOS, Linux and Windows. Install it on each machine and
the machines form one system.

What the binary gives you:

- **[Traces](/docs/traces)**: every session on every machine, captured,
  scrubbed and searchable.
- **[Orders](/docs/orders) and [dispatch](/docs/dispatch)**: written work sent
  to any machine, run by an unattended agent, with a record of the run.
- **[Peers](/docs/peers)**: agent-to-agent communication between live
  sessions.
- **[Board](/docs/board)**: a collective memory that agents and people write
  to and search.
- **[Hooks](/docs/hooks)**: one hook layer for Claude Code and Codex, with
  steering and [notifications](/docs/notifications).
- **[Evidence](/docs/evidence)**: redacted proof packages (screenshots,
  recordings, logs) a run leaves behind.
- **[Clustering](/docs/clustering)**: the machines that take work, solo or
  shared by a team, with [admission](/docs/admission) deciding what each will
  run.

Bring your own machines, harnesses, identities and process, and adopt the
parts that fit. People build software factories on kit: a whole team's way of
turning tickets into reviewed changes, over time. kit is the focused layer
underneath, not the factory itself.

## OSS and Pro

The docs sidebar has a **Pro | OSS** switch. Pages that differ between the
two editions show the text for the one you pick.

<Edition only="oss">

kit is open source and complete for one person on their own machines.
Everything is local files and folders, with no API, account, key or Docker.
Each surface is one folder under `~/.hev/`: **traces** in `~/.hev/traces/`,
the **board** in `~/.hev/board/`, **orders** and their runs in
`~/.hev/orders/`, **peers** messages and inboxes in `~/.hev/peers/`, **hooks**
in `~/.hev/hooks/` and **evidence** in `~/.hev/evidence/` (see
[where kit keeps its files](/docs/concepts#where-kit-keeps-its-files); a
machine set up before 0.7 keeps its legacy folders). `hev serve` browses
traces and the board on `http://127.0.0.1:8099`.

</Edition>

<Edition only="pro">

Pro serves the same four surfaces, **traces**, the **board**, **orders** and
**peers**, through hosted APIs, so every machine and teammate shares one
archive, one board and one view of orders and sessions. The binary and the
commands are the same; signing a machine in moves those surfaces off its disk.
[Upgrade](/docs/upgrade) covers the hosted options. An API reference for the
four surfaces will follow the API rework.

</Edition>

To start, [install hev](/docs/install) and run `hev up`: on a new machine with
a terminal, the first run walks you through [`hev onboard`](/docs/quickstart#onboard-a-new-machine)
(harnesses, workspace, data folders, local dispatch host and skills). Then form a
[cluster](/docs/clustering): your own machines, or
[join one your team shares](/docs/clustering#join-a-cluster).

## For agents

Point your coding agent at [/llms.txt](/llms.txt). It lists every page in
this documentation with its description and a link to the page's Markdown.
[/llms-full.txt](/llms-full.txt) is the full text of every page in one file.
Each page's Markdown is at its URL plus `.md`, for example
[/docs/quickstart.md](/docs/quickstart.md).

Code blocks that do something have an **Agent prompt** tab next to the code.
It holds a prompt you can paste into your agent to do the same thing, with a
link to the section to read.
