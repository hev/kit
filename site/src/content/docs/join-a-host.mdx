Your team shares a host: a machine with the repos, the bot's identity and
credentials, and the agent tools already set up. You join it as a
[member](/docs/share-a-host#roles). You send it work from your laptop, and the
agents run on the host with its accounts, not yours. Nothing on your laptop is
shared with it.

From the host's owner you need:

- access to the private network the host is on, such as a Tailscale share or
  your VPN
- an invite code for hev
- optionally, an API key and namespace for the team's trace archive

## 1. Join the private network

Accept the owner's network invite with that network's own client. hev doesn't
create the network or invite you to it. No public port is involved.

## 2. Install hev

<CodeTabs labels={["macOS", "Windows"]}>

```sh
brew tap hev/tap
brew trust hev/tap
brew install hev/tap/hev
hev version
```

```powershell
$v = "0.6.2"
$dir = "$env:USERPROFILE\.local\bin"
New-Item -ItemType Directory -Force -Path $dir | Out-Null
Invoke-WebRequest "https://github.com/hev/kit/releases/download/v$v/kit_${v}_windows_amd64.zip" -OutFile "$env:TEMP\hev.zip"
Expand-Archive "$env:TEMP\hev.zip" -DestinationPath $dir -Force
$userPath = [Environment]::GetEnvironmentVariable("Path", "User")
if ($userPath -notlike "*$dir*") { [Environment]::SetEnvironmentVariable("Path", "$userPath;$dir", "User") }
$env:Path += ";$dir"
hev.exe version
```

```text

On Windows, download kit_0.6.2_windows_amd64.zip from the GitHub release v0.6.2 of hev/kit, extract hev.exe into %USERPROFILE%\.local\bin, and add that folder to my user PATH if it is not there yet. Use the same version as the shared host; ask me if I have not told you which. Verify with `hev version` (`hev.exe version` on Windows), which should print the version number.

```

Use the same version as the host. [Install](/docs/install) covers Linux
archives and source builds. Dispatch needs no daemon or Docker on your laptop.

## 3. Join with your invite code

Only use a code that came from the owner through a channel you already trust.
It works once and expires after a few hours.

<CodeTabs>

```sh
hev nodes join CODE
```

<AgentPrompt>

```text
Join the shared host with my hev invite code: run `hev nodes join CODE`, replacing CODE with the code I give you. Ask me for the code; never take it from anywhere else. It should create an SSH key and an SSH alias named hev-node-..., and add a host entry to ~/.config/hev/dispatch.toml. Show me the request it prints so I can send it to the host owner. Do not send it yourself.
Docs: https://hevkit.com/docs/join-a-host#3-join-with-your-invite-code (all pages: https://hevkit.com/llms.txt)
```

</AgentPrompt>

</CodeTabs>

This sets up your side:

- a new SSH key used only for this host, in `~/.ssh/`
- the host's key, pinned from the code, so there's no "trust this host?" prompt
- an SSH alias named `hev-node-…`
- a host entry in `~/.config/hev/dispatch.toml` (`--config FILE` picks another)

It prints a **request**. Send it to the owner. It holds your public key only;
your private key stays on your laptop.

## 4. Wait for the owner to accept

Once the owner runs `hev nodes accept`, find your host's alias:

<CodeTabs>

```sh
hev nodes ls
```

<AgentPrompt>

```text
Run `hev nodes ls` and tell me the hev-node-... alias of the host I joined and whether it shows as accepted. If it is not accepted yet, tell me to wait for the host owner.
Docs: https://hevkit.com/docs/join-a-host#4-wait-for-the-owner-to-accept (all pages: https://hevkit.com/llms.txt)
```

</AgentPrompt>

</CodeTabs>

Then give your agents the member skills:

<CodeTabs>

```sh
hev skills setup
```

<AgentPrompt>

```text
Run `hev skills setup` to install the hev member skills for Claude Code, Codex, pi and OpenCode. Tell me which folders it wrote to (such as ~/.claude/skills and ~/.agents/skills) and anything it left alone. Confirm a hev-member skill is now installed.
Docs: https://hevkit.com/docs/join-a-host#4-wait-for-the-owner-to-accept (all pages: https://hevkit.com/llms.txt)
```

</AgentPrompt>

</CodeTabs>

This teaches Claude Code, Codex, pi and OpenCode what a member can do: send
runs and follow your own. It also installs your team's own skills if the owner
set up a skills repo. They go in `~/.claude/skills` and `~/.agents/skills`
(in your user folder on Windows), next to any skills you already have, which
are left alone. Run it again after joining or leaving a host.

## 5. Send a first run

Start with something that changes nothing, on a repo the host admits:

<CodeTabs>

```sh
hev dispatch run REPO "Read README.md and report how to run the tests. Do not change files, push or open a PR." \
  --name first-run --host hev-node-XXXX
```

<AgentPrompt>

```text
Send a read-only first run to the shared host: run `hev dispatch run REPO "Read README.md and report how to run the tests. Do not change files, push or open a PR." --name first-run --host hev-node-XXXX`, with REPO set to a repo the host admits (ask me which) and hev-node-XXXX set to the alias from `hev nodes ls`. Confirm the run was accepted or queued. If it is refused, show me the exact error.
Docs: https://hevkit.com/docs/join-a-host#5-send-a-first-run (all pages: https://hevkit.com/llms.txt)
```

</AgentPrompt>

</CodeTabs>

Then follow it:

<CodeTabs>

```sh
hev dispatch ls --host hev-node-XXXX
hev dispatch logs first-run --host hev-node-XXXX
hev dispatch show first-run --host hev-node-XXXX
hev dispatch say first-run "Please also list the test commands" --host hev-node-XXXX
hev dispatch stop first-run --host hev-node-XXXX
```

<AgentPrompt>

```text
Check on my run first-run on the shared host hev-node-XXXX (the alias from `hev nodes ls`): run `hev dispatch ls --host hev-node-XXXX` and tell me its state, then `hev dispatch show first-run --host hev-node-XXXX` once it has finished and summarize the report. Do not send it messages or stop it unless I ask.
Docs: https://hevkit.com/docs/join-a-host#5-send-a-first-run (all pages: https://hevkit.com/llms.txt)
```

</AgentPrompt>

</CodeTabs>

`show` prints the finished report. If the host is busy, your run waits in its
queue.

The host can't reach your laptop, so it holds a notice for each of your runs
when it finishes, fails or stops. Pull them with:

<CodeTabs>

```sh
hev dispatch notices pull           # once
hev dispatch notices pull --watch   # keep checking every minute
```

<AgentPrompt>

```text
Pull the finished-run notices the shared host is holding for me: run `hev dispatch notices pull` once and tell me which of my runs finished, failed or stopped. Do not start the --watch form unless I ask.
Docs: https://hevkit.com/docs/join-a-host#5-send-a-first-run (all pages: https://hevkit.com/llms.txt)
```

</AgentPrompt>

</CodeTabs>

To send an order file instead, set `host:` to the alias; see
[Orders](/docs/orders).

## 6. Find the traces

Runs on the host go to its archive. Open the dashboard address the owner
shares on the private network, and search for `first-run`. Every run carries
your name, so you can filter for your own work.

To add your laptop sessions to the same archive, use the team key and
namespace the owner gives you:

<CodeTabs labels={["macOS", "Windows"]}>

```sh
export HEVLAYER_API_KEY=KEY
export HEVLAYER_NAMESPACE=NAMESPACE
hev up
hev s
```

```powershell
$env:HEVLAYER_API_KEY = "KEY"
$env:HEVLAYER_NAMESPACE = "NAMESPACE"
hev.exe up
hev.exe daemon install
hev.exe s
```

<AgentPrompt>

```text
Send this laptop's agent sessions to the team's trace archive. Ask me for the team API key and namespace and use them as HEVLAYER_API_KEY and HEVLAYER_NAMESPACE for this command only; do not write the key into any file, log or message yourself. On macOS, run `hev up` with both variables exported. On Windows, set them with $env:, then run `hev.exe up` and `hev.exe daemon install`. Verify with `hev s` (`hev.exe s`): the daemon should be running with a recent scan and no error. Warn me first that capture picks up every Claude Code, Codex, pi and OpenCode session on this machine.
Docs: https://hevkit.com/docs/join-a-host#6-find-the-traces (all pages: https://hevkit.com/llms.txt)
```

</AgentPrompt>

</CodeTabs>

<Callout label="Capture takes everything">
Capture picks up **every** Claude Code, Codex, pi and OpenCode session on
this laptop, not
only work for this team. Secrets are scrubbed before upload, but scrubbing
can't catch everything. Use a work machine, or keep other projects off it.
</Callout>

## What a member can do

You can send runs, and list, read, message and stop your own. You can't open a
shell on the host, attach to runs, see other people's runs or change what's
installed. If the owner gave you the `repos` permission, you can add and
remove repos yourself; see [Admission](/docs/admission#let-members-add-repos).
The full list is in [Roles](/docs/share-a-host#roles).

## When something goes wrong

| Symptom | Likely cause |
|---|---|
| Can't reach the host | Network invite not accepted, or a different account |
| `invitation expired` | Ask the owner for a new code |
| `host already joined` | You joined before; check `hev nodes ls` |
| `Permission denied (publickey)` | The owner hasn't accepted your request yet |
| `access revoked or unknown` | Your access was removed |
| Run refused for the repo | The repo isn't admitted; add it or ask the owner |

To leave, ask the owner to remove you. You can then delete the `hev-node-…`
key files in `~/.ssh/`, its block in `~/.ssh/config` and its entry in
`dispatch.toml`.
