hev kit has two kinds of HTTP API.

- **Local APIs** are served by `hev` on your own machines, on every tier,
  Starter Kit included. `hev serve` serves the trace dashboard and its JSON
  API; `hev board serve` serves the board and its JSON API. They read and
  write what that machine or host keeps.
- **The Field Kit API** is served by us on hevkit.com for teams on
  [Field Kit](/docs/upgrade#field-kit). It is in early access and not yet deployed:
  signing a machine in, traces, the board and usage, with a kit key.

The `hev` CLI is a client of these APIs; agents usually use the CLI instead.
The APIs are for scripts, dashboards and tools of your own.

## Auth

| API | Auth |
| --- | --- |
| Local (`hev serve`, `hev board serve`) | None. `hev serve` listens on `127.0.0.1:8787` unless you pass `--bind` or `--port`; `hev board serve` listens on the address you give it with `--addr` or `[board] addr`. Anything that can reach the port can call it, so keep it on localhost or a network you trust. |
| Field Kit | `Authorization: Bearer hk_…`, the kit key `hev login` saved on the machine. |

A kit key belongs to one person on one machine. It only works against the
Field Kit API, and `hev logout` revokes it.

## Versioning

The local APIs have no version prefix. They ship with `hev` and can change
between kit releases; the [changelog](/docs/changelog) notes changes. Match
the `hev` version on the server when you script against them, and prefer
ignoring fields you don't know over failing on them.

The Field Kit API puts its version in the path (`/v1/…`) for calls made with a
kit key. The sign-in routes under `/cli/` are used by `hev login` and change
with it.

## Errors

Every API answers with an HTTP status code and a JSON body. Status codes mean
what they usually do: `400` for a bad parameter or body, `401` for a missing or
bad key, `403` for a request the key or server mode does not allow, `404` for
an unknown object, `5xx` for a server fault. Each page lists the exceptions it
has.

The Field Kit API's error body is `{"error": "code"}`, with a short code such as
`unauthenticated` or `invalid_grant`. The local APIs' error bodies are given on
each page.
