Joining a team? Start with [Join a cluster](/docs/clustering#join-a-cluster). Node owners
can [share a node with their team](/docs/clustering#share-a-node-with-a-team).

This page takes one machine from nothing to a working harness and a finished
agent run you can search. Starter Kit runs on a single machine in plain files:
no account, no key and no Docker. To connect multiple machines or work as a team,
[upgrade](/docs/upgrade).

This page uses macOS or Linux with Git and `tmux` (`brew install tmux`), plus a
clone of a repository under `~/workspace` with an `origin` remote (this guide
uses `~/workspace/my-project`). On Windows, see [Windows](/docs/windows).

## 1. Install

<CodeTabs>

```sh
brew tap hev/tap
brew trust hev/tap
brew install hev/tap/hev
```

<AgentPrompt>

```text
Install the hev CLI on this Mac or Linux machine with Homebrew: tap hev/tap, trust it, then install hev/tap/hev. Verify with `hev version`, which should print a version number. If Homebrew is missing, stop and tell me instead of installing it another way.
Docs: https://hevkit.com/docs/quickstart#1-install (all pages: https://hevkit.com/llms.txt)
```

</AgentPrompt>

</CodeTabs>

The [install page](/docs/install) covers Linux, Windows and building from source.

## 2. Start kit

<CodeTabs>

```sh
hev up
```

<AgentPrompt>

```text
Run `hev up` to write ~/.hev/config.toml and install the hevd capture daemon (launchd on macOS, systemd user service on Linux). Do not set HEVLAYER_API_KEY; traces should stay in files under ~/.hev/traces/. If it starts onboarding, keep the detected harnesses and the default workspace unless I say otherwise. Then run `hev s` and confirm it shows a recent scan and no error.
Docs: https://hevkit.com/docs/quickstart#2-start-kit (all pages: https://hevkit.com/llms.txt)
```

</AgentPrompt>

</CodeTabs>

On a new machine, `hev up` runs `hev onboard` first: confirm your detected
harnesses and workspace (`~/workspace`), and it writes `~/.hev/config.toml` and
`~/.config/hev/dispatch.toml` (naming this machine `here`), creates `~/.hev/`
(`traces`, `board`, `orders`, `peers`, `hooks`, `evidence`), installs the
bundled agent skills, and starts `hevd` and the local dashboard (`http://127.0.0.1:8099`).

Check daemon health any time with `hev s`.

## 3. Open your harness

You have two ways to drive kit—use whichever fits how you work:

### Option A: The built-in `hev kit` harness

```sh
hev kit
```

`hev kit` starts the built-in terminal harness with first-class dispatch,
traces, board and peers tools already wired in. On Starter Kit it runs out of
the box on free OpenRouter routes with no API key setup.

### Option B: Your existing harness (`claude`, `codex`, `agy`, `pi`, `opencode`)

`hev up` already ran `hev skills setup` to install kit's bundled skills into
your detected harnesses. Re-run it any time after installing a new harness:

```sh
hev skills setup
claude
```

<Callout label="Tip: launching through the Picker">
If you open a session through the Picker instead of bare `claude` or `codex`,
kit injects the workspace system prompt automatically so the agent reaches for
`hev dispatch`, `hev traces` and `hev board` by default.
</Callout>

## 4. Dispatch your first item

From inside your harness (`hev kit`, `claude`, or `codex`), ask the agent to
dispatch a small, safe task on `my-project`:

```text
Dispatch an order on this machine to add a short "Development" section to
README.md in my-project explaining how to run the tests. Commit on the branch,
do not push or open a PR. Walk me through repository admission if needed.
```

The first time you dispatch to a repository, kit's [admission policy](/docs/admission)
checks whether this host accepts it. Your harness will guide you through
approving the repository in `~/.config/hev/dispatch.toml`, then send the order,
create an isolated Git worktree at `~/.hev/orders/<name>/wt`, and run the worker
in tmux.

<Callout label="Workers run unattended">
Dispatched workers run with approvals turned off (`codex exec
--dangerously-bypass-approvals-and-sandbox` or `claude -p
--dangerously-skip-permissions`). The prompt above tells it not to push or open
a PR. Always test on a repository you are comfortable handing to an agent.
</Callout>

Prefer driving from the shell? Save an order file (`first-run.md`) and run:

```sh
hev dispatch first-run.md
hev dispatch ls
hev dispatch logs first-run -f
hev dispatch show first-run
```

## 5. Search its trace and clean up

Once the run finishes, index and search its trace—then remove the worktree
while keeping the branch and receipt:

<CodeTabs>

```sh
hev index
hev traces search "how to run the tests" --order first-run
hev dispatch clean first-run
```

<AgentPrompt>

```text
Index recent sessions with `hev index`, search the trace of my first dispatched run with `hev traces search`, summarize what happened, and clean up the finished worktree with `hev dispatch clean`.
Docs: https://hevkit.com/docs/quickstart#5-search-its-trace-and-clean-up (all pages: https://hevkit.com/llms.txt)
```

</AgentPrompt>

</CodeTabs>

Search matches words locally on Starter Kit. With a [shared archive](/docs/upgrade)
it matches meaning across every machine and teammate in your cluster.
