The dispatch config is TOML. hev reads it from `--config PATH`, then
`HEV_DISPATCH_CONFIG`, then `~/.config/hev/dispatch.toml`. With none, `hev up`
(or [`hev onboard`](/docs/quickstart#onboard-a-new-machine)) writes one naming
this machine as the local host `here` (`default_host = "here"`,
`[hosts.here] local = true`); an existing file is never rewritten. A field hev does
not know is an error: `unknown config key: KEY`.

The same file serves two roles. As a **sender**, `hev dispatch` reads it to
find and reach hosts. As a **target**, the host that runs the work reads its
own copy for admission, notifications and launch settings. The "Read by"
column says which role uses each field.

Most of this page covers the dispatch config. Kit's own settings live in
`~/.hev/config.toml`; the ones other pages document are listed under
[`~/.hev/config.toml`](#hevconfigtoml), and where each surface keeps its
files is under [paths on the host](#paths-on-the-host).

## Top level

| Field | Type | Default | Read by | Meaning |
| --- | --- | --- | --- | --- |
| `cap` | integer | own legacy host cap, then `2` | target | Positive capacity in the target default config. A sender cannot raise it. |
| `workspace` | string | `"~/workspace"` | target | Directory that relative `repo` values resolve against on this machine. A sender's `[hosts.NAME].workspace` overrides it. |
| `default_host` | string | none | sender | Host that `hev dispatch run` prefers when it is reachable and has a free slot. Must name a defined host. |
| `notify` | array of strings | none | target | Command run when a run or validation finishes, as an argv list. No shell. Placeholders: `{name}`, `{state}`, `{summary}`, `{reply}`. |

<CodeTabs>

```toml
cap = 2
workspace = "~/workspace"
default_host = "buildbox"
notify = ["notify-send", "dispatch {name}: {state} {summary}"]
```

`{reply}` is the order's `reply` field. `{summary}` holds the exit code, the
PR URL when there is one, and the validation state and verdict. A failing
notify command is saved as `notify_error` in `result.json` and does not
change the run's state.

## `[admission]`

| Field | Type | Default | Read by | Meaning |
| --- | --- | --- | --- | --- |
| `repos` | array of strings | key absent: admit all | target | Origin URLs or paths this host accepts. `[]` admits none. |

Read only from the target's default config (`HEV_DISPATCH_CONFIG` or
`~/.config/hev/dispatch.toml`), never from `--config` or `config_path`. See
[admission](/docs/admission) for how URLs are matched.

## `[validation]`

Settings for [browser validation](/docs/dispatch). Only orders with
`validation: browser` use them.

| Field | Type | Default | Read by | Meaning |
| --- | --- | --- | --- | --- |
| `host` | string | none | sender, implementer's host | Host that runs validators. Without it, no validation starts automatically. |
| `harness` | string | none | sender, implementer's host | `codex`, `claude` or `agy`. Required when validation runs. |
| `model` | string | none | sender, implementer's host | Model for the validator. The harness and model pair must differ from the implementer's. |
| `allow_same_host` | bool | `false` | sender, implementer's host | Allow the validator on the implementer's host. For local testing. |

## `[hosts.NAME]`

One table per host. `NAME` must match `^[a-z0-9][a-z0-9-]*$` and should be
the same in every machine's config.

| Field | Type | Default | Read by | Meaning |
| --- | --- | --- | --- | --- |
| `local` | bool | `false` | sender | Run on the calling machine with no SSH. |
| `ssh` | string | none | sender | SSH destination, such as `buildbox` or `dev@buildbox`. Required unless `local = true`. May not start with `-`. |
| `cap` | integer | none | sender, legacy target | Optional request ceiling; omitted or `0` sets no sender ceiling. Can lower target capacity, never raise it. Own host entry is the target fallback when top-level `cap` is absent. |
| `os` | string | none | sender | `"windows"` for a Windows host. Anything else is treated as Unix. |
| `workspace` | string | none | sender | Workspace for relative `repo` values on this host. Overrides the host's top-level `workspace`. Accepts Windows drive and UNC paths. |
| `path_prefix` | array of strings | none | sender | Directories put in front of PATH for every remote call. Unix only. `~/` expands on the host. |
| `namespace` | string | none | sender | Set as `HEVLAYER_NAMESPACE` in the worker's environment. |
| `harness_wrapper` | array of strings | none | target, then sender | Argv run before the harness, followed by `--`, the harness and its arguments. The host's own entry wins. The sender's is used only when the host has none. |
| `config_path` | string | none | sender | Dispatch config the host's supervisor reads, for example an isolated smoke-test file. Relative paths resolve next to the file that names them. `~/` expands on the host. Does not change admission. |
| `env` | array of strings | none | target | Extra environment variable names to pass to the worker. Values come only from the admitting process's environment. The old `[hosts.NAME.env]` table is rejected. |

<CodeTabs>

```toml
[hosts.buildbox]
ssh = "buildbox"
cap = 8
namespace = "team-traces"
path_prefix = ["~/.local/bin"]
env = ["NPM_TOKEN"]
```

A host entry is invalid when its name does not match the pattern, its `cap`
is negative, or neither `local` nor `ssh` is set. A sender stops on any invalid
entry. A target only requires its own entry to be valid and prints a
`warning:` for the rest.

The supervisor also sets `HEV_RUN` to the run's name in every worker's
environment, and `TRACEPARENT`, `HEV_TRACE_ID` and `HEV_SPAN_ID` in a traced
worker's, replacing any values it inherited. See [ask-rooted traces](/docs/traces#ask-rooted-traces).

`workspace`, `harness_wrapper` and `config_path` need a `hev` version that
supports per-host launch settings on every machine that reads the file.
Older versions stop with `unknown config key`.

## `[harnesses.NAME]`

Optional per-harness launch settings in the target's dispatch config, for
`codex`, `claude` or `agy`. They apply to every launch of that harness on the
host: dispatch runs, validators and orchestrator rounds.

| Field | Type | Default | Read by | Meaning |
| --- | --- | --- | --- | --- |
| `model_provider` | string | none | target | `agy` only. Passed as `--settings '{"modelProvider":"..."}'`. Without it, `gemini` is passed whenever `GEMINI_API_KEY` is set for the harness. |
| `env_refs` | table | none | target | Environment names mapped to secret references (`op://`, `azkv://`, `secret://`), resolved through [hev secrets](/docs/secrets) just before the harness starts. Values never reach `meta.json`, the log or errors. |

```toml
[harnesses.agy]
model_provider = "gemini"

[harnesses.agy.env_refs]
GEMINI_API_KEY = "op://example/gemini-key/credential"
```

## `[workspace]`

<Edition only="oss">

In OSS every run works in a plain `git worktree`; there is nothing to
configure. `[workspace]` is a Pro setting.

</Edition>

<Edition only="pro">

<Callout label="Rolling out in 0.7">
`[workspace]` ships with Pro dispatch workspaces on the 0.7 train (PR #325),
not yet in a release. Its Pro modes need a valid Kit Pro
[license](/docs/licensing) on the receiving host.
</Callout>

How the receiving host provisions run workspaces. See
[Dispatch: workspaces](/docs/dispatch#workspaces).

| Field | Type | Default | Read by | Meaning |
| --- | --- | --- | --- | --- |
| `mode` | string | `"auto"` | target | `auto`: Pro features when licensed, else plain Git worktrees. `oss`: always plain Git worktrees. `pro`: require a valid Pro license. |
| `root` | string | `"~/workspace"` | target | Repository search directory. The legacy top-level `workspace` string still sets it. |
| `driver` | string | `"cow"` | target | `cow`: APFS clone or Linux reflink, falling back to Git checkout. `git`: always Git checkout. |
| `auto_compact_done` | bool | `false` | target | Attempt `hev dispatch compact` after successful work. |

```toml
cap = 8

[workspace]
mode = "auto"
root = "~/workspace"
driver = "cow"
auto_compact_done = false
```

</Edition>

## `~/.hev/config.toml`

Kit's own config (`hev config path` prints it; `HEV_CONFIG` selects another).
These tables are documented on their own pages:

| Table | What it sets | See |
| --- | --- | --- |
| `[layer]`, `[archive]`, `[board]` | Where traces and the board are kept | [below](#where-data-is-kept) |
| `[capture]` | Scan interval, redaction, images, `agy_data_dir` | [Traces](/docs/traces) |
| `[hooks]` | `enabled`, `timeout`, `halt_timeout` | [Hooks](/docs/hooks#fail-open) |
| `[notify.slack]` | Attention notices to a Slack user or channel | [Notifications](/docs/notifications#slack) |
| `[feed]` | The Slack feed: channel, token and model references, events, boards, `client_roots` | [Notifications](/docs/notifications#slack-feed) |
| `[evidence]` | `dir`, where evidence packages live (default `~/.hev/evidence`; `HEV_EVIDENCE_DIR` wins) | [Evidence](/docs/evidence) |
| `[license]` | `key` or `key_ref`, the Kit Pro license | [Licensing](/docs/licensing) |
| `[[skills.sources]]` | Packs pinned on the skills shelf | [Skills shelf](/docs/skills-shelf) |

`~/.hev/onboard.toml` (mode 0600) holds the answers from
[`hev onboard`](/docs/quickstart#onboard-a-new-machine), offered as defaults
on a re-run. It is not a config file: deleting it only makes the next `hev up`
on a terminal offer onboarding again when there is no other config.

## Where data is kept

Starter Kit keeps everything in files; [Pro Kit](/docs/upgrade#pro-kit),
for working as a team on your own hev layer, moves traces and the board there. A hev layer API key is the only
thing that decides which. These settings are in
`~/.hev/config.toml` (`hev config path` prints the path), not the dispatch
config.

| Setting | Default | Meaning |
| --- | --- | --- |
| `[layer] api_key` | none | hev layer key for traces. With none, traces go to the file archive. `hev up` with `HEVLAYER_API_KEY` exported, `hev init` and `hev join` write it. |
| `[layer] namespace` | `"hev-traces"` | Archive name. With no key, it is the directory under the archive root. |
| `[archive] dir` | `~/.hev/traces` (a kept `~/.hev/archive` on a host set up before 0.7) | Root of the file archive. `HEV_ARCHIVE_DIR` overrides it. |
| `[board] dir` | `~/.hev/board` | Where the board keeps threads with no key. `HEV_BOARD_DIR` overrides it. |

Environment variables count as a key too: `HEVLAYER_API_KEY`, or
`HEVLAYER_API_KEY_OP_REF` naming a 1Password item read with `op`. The board
server reads its key only from the environment (`HEVLAYER_API_KEY`,
`HEVLAYER_API_KEY_OP_REF` or `FACTORY_BOARD_LAYER_API_KEY`), never from
`[layer] api_key`. A key that is set but can't be read is an error; kit never
falls back to files.

The dispatch config has no storage setting. Run records, queues, peers and
admission are files with or without a key. `[hosts.NAME].namespace` only tells
a worker which archive its sessions belong to.

## Paths on the host

| Path | What it is |
| --- | --- |
| `~/.config/hev/dispatch.toml` | Default dispatch config. |
| `~/.hev/config.toml` | Kit's config. |
| `~/.hev/onboard.toml` | Onboarding answers. |
| `~/.hev/orders/NAME/` | One run's record: `order.md`, `meta.json`, `status.md`, `report.md`, `log`, `result.json`, `inbox.md`. `HEV_ORDERS_DIR` moves the orders folder. |
| `~/.hev/orders/NAME/wt` | The run's workspace, on branch `d/NAME`. |
| `~/.hev/orders/NAME-vN/` | A browser validator's record for run `NAME`. |
| `~/.hev/orders/NAME/contexts/N/` | The [context bundle](/docs/context) attempt `N` was given. |
| `~/.hev/orders/NAME/context-recipe.json` | A [carried context recipe](/docs/context#a-recipe-for-one-dispatch), pinned at the run's first build. |
| `~/.hev/traces/NAMESPACE/` | The file archive, used with no key. |
| `~/.hev/board/` | The board's threads with no key. |
| `~/.hev/peers/` | Peers messages, inboxes and receipts. `HEV_PEERS_STATE` moves it. |
| `~/.hev/hooks/` | `events.jsonl` and `warnings.log` from [hooks](/docs/hooks). |
| `~/.hev/evidence/` | [Evidence](/docs/evidence) packages. |
| `~/.hev/secrets/` | The [secrets](/docs/secrets) cache's read log. |
| `~/.hev/feed/` | The [Slack feed](/docs/notifications#slack-feed)'s spool, thread map and sender log. |

A host set up before the unified layout keeps `~/dispatch/` (run records and
worktrees), `~/.hev/archive/` (traces) and `~/.local/state/peers-v2/` (peers)
where they are: each surface uses its `~/.hev/<surface>/` folder when that
exists, else the legacy folder when that exists. See
[where kit keeps its files](/docs/concepts#where-kit-keeps-its-files).

## `[foh]`

The [`hev kit` harness](/docs/kit) reads these optional strings from
`~/.hev/config.toml`.

| Field | Meaning |
| --- | --- |
| `model` | Default model ID. `--model` and `HEV_FOH_MODEL` take precedence. |
| `summary_model` | Model for inline tool summaries. `HEV_SUMMARY_MODEL` takes precedence. If unset, the harness picks one based on the available providers. |
| `docs_url` | Documentation base URL for the harness. Defaults to `https://hevkit.com/docs`. `HEV_DOCS_URL` takes precedence. |
