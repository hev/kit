The dispatch config is TOML. hev reads it from `--config PATH`, then
`HEV_DISPATCH_CONFIG`, then `~/.config/hev/dispatch.toml`. A field hev does
not know is an error: `unknown config key: KEY`.

The same file serves two roles. As a **sender**, `hev dispatch` reads it to
find and reach hosts. As a **target**, the host that runs the work reads its
own copy for admission, notifications and launch settings. The "Read by"
column says which role uses each field.

Most of this page is the dispatch config. Capture, search and board settings
live in `~/.hev/config.toml`; [where data is kept](#where-data-is-kept) covers
the settings that decide whether data stays in files or goes to hev layer.

## Top level

| Field | Type | Default | Read by | Meaning |
| --- | --- | --- | --- | --- |
| `cap` | integer | own legacy host cap, then `2` | target | Positive capacity in the target default config. A sender cannot raise it. |
| `workspace` | string | `"~/workspace"` | target | Directory that relative `repo` values resolve against on this machine. A sender's `[hosts.NAME].workspace` overrides it. |
| `default_host` | string | none | sender | Host that `hev dispatch run` prefers when it is reachable and has a free slot. Must name a defined host. |
| `notify` | array of strings | none | target | Command run when a run or validation finishes, as an argv list. No shell. Placeholders: `{name}`, `{state}`, `{summary}`, `{reply}`. |

```toml
cap = 2
workspace = "~/workspace"
default_host = "buildbox"
notify = ["notify-send", "dispatch {name}: {state} {summary}"]
```

`{reply}` is the order's `reply` field. `{summary}` holds the exit code, the
PR URL when there is one, and the validation state and verdict. A failing
notify command is saved as `notify_error` in `result.json` and does not
change the run's state.

## `[admission]`

| Field | Type | Default | Read by | Meaning |
| --- | --- | --- | --- | --- |
| `repos` | array of strings | key absent: admit all | target | Origin URLs or paths this host accepts. `[]` admits none. |

Read only from the target's default config (`HEV_DISPATCH_CONFIG` or
`~/.config/hev/dispatch.toml`), never from `--config` or `config_path`. See
[admission](/docs/admission) for how URLs are matched.

## `[validation]`

Settings for [browser validation](/docs/dispatch). Only orders with
`validation: browser` use them.

| Field | Type | Default | Read by | Meaning |
| --- | --- | --- | --- | --- |
| `host` | string | none | sender, implementer's host | Host that runs validators. Without it, no validation starts automatically. |
| `harness` | string | none | sender, implementer's host | `codex` or `claude`. Required when validation runs. |
| `model` | string | none | sender, implementer's host | Model for the validator. The harness and model pair must differ from the implementer's. |
| `allow_same_host` | bool | `false` | sender, implementer's host | Allow the validator on the implementer's host. For local testing. |

## `[hosts.NAME]`

One table per host. `NAME` must match `^[a-z0-9][a-z0-9-]*$` and should be
the same in every machine's config.

| Field | Type | Default | Read by | Meaning |
| --- | --- | --- | --- | --- |
| `local` | bool | `false` | sender | Run on the calling machine with no SSH. |
| `ssh` | string | none | sender | SSH destination, such as `buildbox` or `dev@buildbox`. Required unless `local = true`. May not start with `-`. |
| `cap` | integer | none | sender, legacy target | Optional request ceiling; omitted or `0` sets no sender ceiling. Can lower target capacity, never raise it. Own host entry is the target fallback when top-level `cap` is absent. |
| `os` | string | none | sender | `"windows"` for a Windows host. Anything else is treated as Unix. |
| `workspace` | string | none | sender | Workspace for relative `repo` values on this host. Overrides the host's top-level `workspace`. Accepts Windows drive and UNC paths. |
| `path_prefix` | array of strings | none | sender | Directories put in front of PATH for every remote call. Unix only. `~/` expands on the host. |
| `namespace` | string | none | sender | Set as `HEVLAYER_NAMESPACE` in the worker's environment. |
| `harness_wrapper` | array of strings | none | target, then sender | Argv run before the harness, followed by `--`, the harness and its arguments. The host's own entry wins. The sender's is used only when the host has none. |
| `config_path` | string | none | sender | Dispatch config the host's supervisor reads, for example an isolated smoke-test file. Relative paths resolve next to the file that names them. `~/` expands on the host. Does not change admission. |
| `env` | table | none | target | Extra environment variable names to pass to the worker. Only the keys are used. Values come from the admitting process's environment. |

```toml
[hosts.buildbox]
ssh = "buildbox"
cap = 8
namespace = "team-traces"
path_prefix = ["~/.local/bin"]

[hosts.buildbox.env]
NPM_TOKEN = ""
```

A host entry is invalid when its name does not match the pattern, its `cap`
is negative, or neither `local` nor `ssh` is set. A sender stops on any invalid
entry. A target only requires its own entry to be valid and prints a
`warning:` for the rest.

From 0.7, the supervisor also sets `TRACEPARENT`, `HEV_TRACE_ID`,
`HEV_SPAN_ID` and `HEV_RUN` in a traced worker's environment, replacing any
values it inherited. They are not forwarded with `env`. See
[ask-rooted traces](/docs/traces#ask-rooted-traces).

`workspace`, `harness_wrapper` and `config_path` need a `hev` version that
supports per-host launch settings on every machine that reads the file.
Older versions stop with `unknown config key`.

## Where data is kept

kit on its own keeps everything in files; [kit + layer](/docs/kit-and-layer)
moves traces and the board to hev layer. A hev layer API key is the only
thing that decides which. These settings are in
`~/.hev/config.toml` (`hev config path` prints the path), not the dispatch
config.

<Callout label="Coming in 0.7">
The file archive and `[archive] dir` arrive in 0.7, and so do the board's
file storage and `dir`. In 0.6.2, no key means a local hev layer in Docker.
</Callout>

| Setting | Default | Meaning |
| --- | --- | --- |
| `[layer] api_key` | none | hev layer key for traces. With none, traces go to the file archive. `hev up` with `HEVLAYER_API_KEY` exported, `hev init` and `hev join` write it. |
| `[layer] namespace` | `"hev-traces"` | Archive name. With no key, it is the directory under the archive root. |
| `[archive] dir` | `~/.hev/archive` | Root of the file archive. `HEV_ARCHIVE_DIR` overrides it. |
| `[board] dir` | `~/.hev/board` | Where the board server keeps threads with no key. `HEV_BOARD_DIR` overrides it. |

Environment variables count as a key too: `HEVLAYER_API_KEY`, or
`HEVLAYER_API_KEY_OP_REF` naming a 1Password item read with `op`. The board
server reads its key only from the environment (`HEVLAYER_API_KEY`,
`HEVLAYER_API_KEY_OP_REF` or `FACTORY_BOARD_LAYER_API_KEY`), never from
`[layer] api_key`. A key that is set but can't be read is an error; kit never
falls back to files.

The dispatch config has no storage setting. Run records, queues, peers and
admission are files with or without a key. `[hosts.NAME].namespace` only tells
a worker which archive its sessions belong to.

## Paths on the host

| Path | What it is |
| --- | --- |
| `~/.config/hev/dispatch.toml` | Default dispatch config. |
| `~/dispatch/NAME/` | One run's record: `order.md`, `meta.json`, `status.md`, `report.md`, `log`, `result.json`, `inbox.md`. |
| `~/dispatch/NAME/wt` | The run's Git worktree, on branch `d/NAME`. |
| `~/dispatch/NAME-vN/` | A browser validator's record for run `NAME`. |
| `~/dispatch/NAME/contexts/N/` | **Coming in 0.7.** The [context bundle](/docs/context) attempt `N` was given. |
| `~/.hev/archive/NAMESPACE/` | **Coming in 0.7.** The file archive, used with no key. |
| `~/.hev/board/` | **Coming in 0.7.** The board's threads with no key, on the host running `hev board serve`. |
