hev kit is one binary, `hev`. Install it on every machine that sends or runs
work. The daemon, `hevd`, is the same binary running as a service.

## macOS and Linux

The release pipeline builds the tap's `hev` formula for macOS and Linux:

```sh
brew install hev/tap/hev
```

After `brew tap hev/tap`, `brew install hev` also selects the tap formula.
Bare `brew install hev` without a tap would need a homebrew-core formula;
that is not part of this release. The older `hev/tap/kit` name remains a
compatibility formula.

<Callout label="0.6 is unreleased">
The formula and release archive support are on `main`. Until 0.6 is tagged,
build from source to use the features documented here, on any OS with Go
1.26 or later:

```sh
go install github.com/hev/kit/cmd/hev@main
```
</Callout>

This puts `hev` in `$(go env GOPATH)/bin`. Add it to the PATH seen by SSH,
or use `path_prefix` in dispatch config. See [headless machines](/docs/headless).

## Release archives

The release pipeline produces `kit_VERSION_darwin_ARCH.tar.gz` and
`kit_VERSION_linux_ARCH.tar.gz` for `arm64` and `amd64`, plus
`kit_VERSION_windows_amd64.zip`. Download from
[GitHub releases](https://github.com/hev/kit/releases) once the version is
tagged and check `checksums.txt`. Extract `hev` (or `hev.exe`) to a directory
on your user PATH.

Windows 11 on AMD64 supports capture and dispatch targets. Until 0.6 is
tagged, use the source install above or build from a clone:

```powershell
git clone https://github.com/hev/kit.git
cd kit
go build -o hev.exe ./cmd/hev
```

Keep the binary at a stable absolute path. The [Windows page](/docs/windows)
covers Task Scheduler.

## Start the daemon

On macOS, `hev up` starts everything a machine needs:

```sh
hev up
```

It runs these in Docker:

- the hev layer gateway (community edition), which stores and searches traces
- its Postgres store and a CPU embedding model
- the kit dashboard, at `http://127.0.0.1:8099`

It also writes `~/.hev/config.toml`, installs `hevd` under launchd, and
installs the bundled skills for Claude Code and Codex. Your transcripts stay
on the machine. `hev up` needs Docker running and no key. With
`TURBOPUFFER_API_KEY` exported, the archive goes to your
[turbopuffer](https://turbopuffer.com) account instead.

Running `hev up` again checks the stack, refreshes bundled skills and
restarts capture when the installed binary needs updating.
`hev down` stops the containers and unloads the daemon. The archive stays in its
Docker volume.

On Linux, `hev up` also installs and starts `hevd.service` under systemd's
user manager. `hev daemon install`, `start`, `status`, `stop` and `uninstall`
manage the user service. On headless hosts, enable lingering for your user
with `loginctl enable-linger` so it survives logout. Without a usable user
manager, `hev up` reports the problem; run `hev d` in the foreground under
your own supervisor.

## Bundled skills

`hev up` installs version-stamped skills for existing Claude Code and Codex
homes. `hev skills check` reports missing, stale or locally edited skills.
`hev skills sync` repairs missing and stale copies; `--force` also replaces
local edits. Check the diff before forcing a replacement.

To send traces to an existing Layer instead of a local one, run `hev init` and
enter its endpoint, API key and namespace. `hev config show` prints the
effective config with secrets redacted.

## Verify

```sh
hev s
```

`hev s` reports the daemon's last run, units indexed and last error. Then
search:

```sh
hev traces search "why did the preflight fail"
```

Dispatch needs no daemon and no extra install. It needs a config file on the
sending machine; the [quickstart](/docs/quickstart) writes one.
